# Contributing

Thanks for your interest in contributing! This document explains how to get involved with any project under this organization.

## Before You Start

- Check the Issues and Discussions tabs of the specific repository you want to contribute to — your idea or bug may already be raised there.
- For large changes (new language features, major refactors), open a Discussion first to talk it through before writing code — this saves everyone time.
- For small fixes (typos, small bugs), feel free to jump straight to a Pull Request.

## How to Contribute

1. **Fork** this repository to your own GitHub account.
2. **Clone** your fork locally.
3. Create a new branch for your change:
   ```
   git checkout -b fix/short-description
   ```
4. Make your changes.
5. Test your changes locally if possible.
6. Commit with a clear message describing what changed and why.
7. Push your branch to your fork.
8. Open a **Pull Request** against the `main` branch of this repository.

## Pull Request Guidelines

- Keep PRs focused — one fix or feature per PR is easier to review than several bundled together.
- Describe **what** changed and **why** in the PR description.
- Make sure the CI check (build-and-test) passes before requesting review.
- Be responsive to review comments — conversations must be resolved before merging.

## Code Style

- Keep code readable and consistent with the surrounding style in the file you're editing.
- Add comments for anything non-obvious, especially in compiler/parser logic.

## Reporting Bugs

Use the **Bug Report** issue template and include as much detail as possible — steps to reproduce, expected vs. actual behavior, and your environment.

## Suggesting Features

Use the **Feature Request** issue template, or start a Discussion under "Ideas" if it's still an early thought.

## Good First Issues

New to the project? Look for issues labeled **`good first issue`** — these are scoped to be approachable for newcomers.

## Questions

If anything here is unclear, open a Discussion in the repository you're working on — we're happy to help.
